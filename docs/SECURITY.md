# Политика информационной безопасности проекта PhoneFix

Документ описывает, как в проекте **PhoneFix** (React + Laravel 11 + MySQL) защищаются
данные пользователей, доступ к функциям и сама инфраструктура. Политика дополняет
[«Политику конфиденциальности»](../frontend/src/pages/Privacy.jsx) — публичную страницу
`/privacy`, которую видит посетитель сайта.

Версия документа: 1.0 от 13.10.2026.
Область действия: код проекта (`backend/`, `frontend/`), база данных `phonefix`,
сервер развёртывания (VPS по заданию, IP-адрес из панели).

---

## 1. Цели и принципы

1. **Минимизация данных** — собираем только то, без чего нельзя выполнить ремонт: имя,
   телефон, e-mail, модель устройства и описание неисправности.
2. **Разграничение доступа** — каждая роль видит только свои данные (см. §3).
3. **Защита по умолчанию** — в продакшене выключена отладка, ограничена частота запросов,
   закрыты служебные файлы, наружу отдаётся только белый список настроек.
4. **Проверяемость** — все решения подтверждаются автотестами (61 тест) и этим документом.

## 2. Архитектура и границы доверия

| Компонент | Что это | Граница доверия |
| --- | --- | --- |
| SPA (`frontend/`, сборка в `backend/public/app`) | React 18 в браузере | **Недоверенная среда**: любой запрос можно подделать |
| API (`backend/`, Laravel 11) | Единственный источник правды, вся проверка прав здесь | Доверенная зона |
| MySQL | Хранение данных | Доступен только с localhost сервера |
| nginx | Отдача статики и проксирование PHP-FPM | Доверенная зона |

Ключевой принцип: **браузеру не доверяем**. Скрытые кнопки и проверки в React —
только удобство; любое действие повторно проверяется на сервере
(`auth:sanctum`, `role:admin`, сверка владельца заявки).

## 3. Аутентификация и управление сессиями

* Вход по e-mail и паролю, `POST /api/auth/login`; пароль проверяется `Hash::check`
  (bcrypt), одинаковое сообщение для «нет пользователя» и «неверный пароль».
* Выдаётся токен Laravel Sanctum (`createToken('spa')`), который передаётся в заголовке
  `Authorization: Bearer …`.
* **Срок жизни токена — 7 дней** (`SANCTUM_TOKEN_EXPIRATION=10080`, `config/sanctum.php`).
  Ранее токены были бессрочными — исправлено.
* **Смена пароля или e-mail требует текущий пароль** (`current_password`,
  `AuthController::updateProfile`). После смены пароля все остальные токены
  отзываются — украденный токен перестаёт работать.
* Заблокированный пользователь (`is_active = false`) не проходит ни в админку
  (middleware `role`), ни в клиентские разделы (middleware `active`), даже с живым токеном.

## 4. Авторизация и роли

| Роль | Права |
| --- | --- |
| `client` | свои заявки и история, отмена своей заявки, отзыв по выполненной работе, профиль |
| `technician` | доступ к расписанию и заявкам в админ-контуре (ограничен middleware) |
| `admin` | вся админ-панель: заявки, услуги и цены, мастера, расписание, отзывы, лиды, статьи, тексты, пользователи |

* Админ-маршруты: `/api/admin/*` под `auth:sanctum` + `role:admin`
  (`routes/api.php`, `EnsureUserHasRole`).
* Роль при регистрации жёстко фиксируется как `client` — повысить её через API нельзя.
* Владелец данных проверяется на сервере: заявку и отзыв видит/меняет только их автор
  (`AppointmentController::show/cancel`, `ReviewController::store`).
* Защита от снятия прав: нельзя удалить себя и нельзя оставить систему без администратора.

## 5. Пароли

* Хранятся только в виде bcrypt-хеша (каст `hashed`, поле скрыто в API-ответах).
* Минимальная длина — **8 символов** (`register`, `updateProfile`, админские формы).
* Мастеру при создании пароль генерируется случайным (`Str::password(16)`) и показывается
  администратору один раз — угадываемого пароля `password` больше нет.
* Рекомендация на будущее: подключить проверку утечек (`Password::uncompromised()`).

## 6. Ограничение частоты запросов (антибрутфорс и антиспам)

Лимиты заданы в `AppServiceProvider::configureRateLimiting()` и включены на маршрутах:

| Маршрут | Лимит | Смысл |
| --- | --- | --- |
| `POST /api/auth/login` | 5 / мин на «e-mail + IP» | защита от подбора пароля |
| `POST /api/auth/register` | 10 / мин на IP | защита от массовых аккаунтов |
| `POST /api/public/leads` | 10 / мин на IP | защита от спама заявок |
| `GET /api/public/*` | 240 / мин на IP | защита от флуда и выкачки |
| весь `/api/*` | `throttleApi()` — 240 / мин | общий предохранитель |

При превышении возвращается `429 Too Many Requests`.

Сайт работает за прокси панели, поэтому в `bootstrap/app.php` включено
`$middleware->trustProxies(at: '*')`: реальный IP клиента берётся из `X-Forwarded-For`.
Без этого лимиты считали бы всех посетителей одним IP и были бы общими на весь интернет.

## 7. Валидация и целостность данных

* Все данные проходят `validate()`; массового присваивания (`$request->all()`) в проекте нет.
* Онлайн-запись: время проверяется на попадание в **рабочую сетку** (`work_day_start`,
  `work_day_end`, `slot_step_minutes`) и на **пересечение** с уже занятыми интервалами —
  записаться на 03:17 или «поверх» чужой записи через API нельзя.
* От двойного бронирования защищают транзакция + `lockForUpdate()` и
  `UNIQUE(technician_id, starts_at)` в БД.
* Отзыв можно оставить только по своей выполненной заявке, один раз на услугу,
  и он уходит на модерацию администратору.
* Пагинация админских списков ограничена (`per_page` не больше 100) — нельзя выкачать
  всю таблицу одним запросом.

## 8. Защита от типовых атак

| Угроза | Мера | Где реализовано |
| --- | --- | --- |
| Подбор пароля | лимит 5/мин + bcrypt + мин. длина 8 | `AppServiceProvider`, `AuthController` |
| Спам форм и лидов | лимит 5/мин на `leads` | `routes/api.php` |
| SQL-инъекции | только Eloquent и bindings, `raw()` со статичными агрегатами | `app/Models`, контроллеры |
| XSS | React экранирует вывод, `dangerouslySetInnerHTML` не используется, CSP | `frontend/src`, `SecurityHeaders` |
| CSRF | токенная аутентификация (cookie-сессия для API не используется) | Sanctum |
| Кража токена | срок 7 дней, отзыв остальных токенов при смене пароля | `config/sanctum.php`, `AuthController` |
| Захват аккаунта | подтверждение текущего пароля при смене пароля/e-mail | `AuthController::updateProfile` |
| Доступ к чужим данным (IDOR) | сверка владельца на сервере | `AppointmentController`, `ReviewController` |
| Повышение роли | роль задаётся сервером, поле `role` не принимается от клиента | `AuthController::register` |
| Кликджекинг | `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'` | `SecurityHeaders`, nginx |
| MIME-sniffing | `X-Content-Type-Options: nosniff` | `SecurityHeaders`, nginx |
| Утечка настроек | публичный API отдаёт только белый список ключей (`Setting::PUBLIC_KEYS`) | `Setting::publicMap()` |
| Утечка `.env` | файл вне git и вне архива развёртывания, nginx закрывает dot-файлы | `.gitignore`, `docs/DEPLOY.md` |
| Раскрытие отладочной информации | `APP_DEBUG=false`, `LOG_LEVEL=info` в проде | `.env.example`, `docs/DEPLOY.md` |

## 9. Инфраструктура и развёртывание

* Корень сайта — `backend/public`; `.env`, `storage`, `vendor` снаружи веб-доступа.
* nginx отдаёт заголовки `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy`,
  скрывает версию (`server_tokens off`) и заголовок `X-Powered-By`.
* Те же заголовки добавляет middleware `SecurityHeaders` — защита работает и без nginx.
* Права: владелец `www-data`, каталоги 775, запись только в `storage` и `bootstrap/cache`.
* Пароль БД хранится только в `.env` сервера, не в репозитории и не в архиве.
* **Ограничение:** по заданию сайт доступен по IP без TLS — трафик идёт по HTTP.
  Рекомендация: включить HTTPS (Let's Encrypt или самоподписанный сертификат) и
  `SESSION_SECURE_COOKIE=true`; заголовок HSTS добавлен в конфиг nginx
  в [DEPLOY.md](DEPLOY.md) — включается вместе с TLS.

## 10. Резервное копирование и восстановление

```bash
# ежедневный дамп базы (пример задания cron)
mysqldump --single-transaction phonefix > /var/backups/phonefix-$(date +%F).sql

# восстановление
mysql phonefix < /var/backups/phonefix-2026-10-13.sql
```

Каталог резервных копий закрыт от веб-доступа; копии хранятся вне сервера приложения.

## 11. Журналирование

* Пишутся только технические события Laravel (`storage/logs/laravel.log`).
* Персональные данные (телефоны, e-mail, тексты заявок) в логи не выводятся —
  в коде нет `Log::`/`logger()` с данными запроса.
* Уровень логирования в проде — `info` (без `debug`-подробностей и SQL).

## 12. Действия при инциденте

1. Заблокировать подозрительную учётную запись (`is_active = false`) — доступ отзывается сразу.
2. Сменить пароль администратора (все остальные токены отзовутся автоматически).
3. Проверить `storage/logs/laravel.log` и список токенов `personal_access_tokens`.
4. При компрометации БД — восстановить данные из последней резервной копии
   и сменить пароль пользователя MySQL.
5. Зафиксировать инцидент и причину, обновить эту политику.

## 13. Принятые риски и план развития

| Риск | Решение сейчас | План |
| --- | --- | --- |
| Токен хранится в `localStorage` | срок 7 дней, отзыв при смене пароля, CSP ограничивает источники | переход на httpOnly-cookie |
| Нет подтверждения e-mail | заявку можно оставить без аккаунта, регистрация ограничена лимитом | `MustVerifyEmail` для чувствительных действий |
| Ответ `403` вместо `404` на чужую заявку | сами данные закрыты, известен только факт существования ID | отдавать `404` (сейчас зафиксировано тестами) |
| `status` отзыва в `$fillable` | статус всегда ставится явно в контроллере | убрать из `$fillable` при следующем рефакторинге |
| Нет двухфакторной аутентификации | — | 2FA для роли `admin` |

## 14. Ответственность и пересмотр

* Ответственный за информационную безопасность проекта — администратор системы
  (роль `admin`).
* Политика пересматривается при изменении функциональности, перед защитой проекта
  и не реже одного раза в семестр.
* Публичная версия для пользователей — страница `/privacy`
  (текст хранится в настройке `privacy_policy` и правится в админ-панели).
