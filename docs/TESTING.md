# Чек-лист проверки проекта

## 0. Быстрая проверка (рекомендуется в первую очередь)

```powershell
# из корня проекта
.\check-env.ps1     # версии PHP/Node, расширения, соединение с MySQL, наличие файлов
.\run-tests.ps1     # 61 автотест на SQLite в памяти
```

Если PowerShell отвечает `running scripts is disabled on this system`, используйте
`.cmd`-обёртки из корня проекта — они сами обходят политику запуска:

```
check-env.cmd
run-tests.cmd
```

Скрипты подскажут, чего не хватает, ещё до первого запуска. Ниже — ручной чек-лист
для демонстрации преподавателю.

## Автотесты (61 тест)

Запуск: `.\run-tests.ps1` или `cd backend; php artisan test`.
База — SQLite в памяти, рабочая MySQL не затрагивается.

| Файл | Тестов | Что проверяет |
| --- | --- | --- |
| `tests/Unit/SlotServiceTest.php` | 8 | генерация слотов по рабочим часам, шаг сетки, исключение занятого и прошедшего времени, резервирование |
| `tests/Feature/AuthTest.php` | 9 | регистрация (роль `client`, хеш пароля), запрет создать админа через регистрацию, вход, блокировка, токен, выход |

| `tests/Feature/PublicApiTest.php` | 10 | настройки сайта, главная, фильтры каталога, скрытые услуги, лиды из модального окна, блог, отзывы |

## Ручной чек-лист для защиты

Отмечайте пункты при демонстрации преподавателю: каждый закрывает конкретное требование задания.

## 1. Архитектура и база данных

- [ ] В MySQL создано **10 связанных таблиц** (`users`, `services`, `technicians`, `schedules`, `appointments`, `reviews`, `leads`, `articles`, `settings` + служебные).
- [ ] В phpMyAdmin/Adminer видно внешние ключи: `appointments.client_id → users.id`, `appointments.service_id → services.id`, `appointments.technician_id → technicians.id`, `appointments.schedule_id → schedules.id`, `reviews.user_id → users.id`, `schedules.technician_id → technicians.id`.
- [ ] В таблице `users` поле `role` принимает значения `client`, `technician`, `admin`.

## 2. Ролевая модель

- [ ] Регистрация создаёт пользователя с ролью `client`.
- [ ] Клиент заходит в `/account`, видит свои заявки, может отменить и оставить отзыв.
- [ ] Обычный клиент при попытке открыть `/admin` перенаправляется на главную.
- [ ] Администратор (`admin@phonefix.ru` / `admin123`) открывает `/admin` и видит дашборд.
- [ ] API админки возвращает `403` для неадминистратора.

## 3. Многостраничность и роутинг

- [ ] Работают страницы: `/`, `/services`, `/services/:slug`, `/technicians`, `/booking`, `/reviews`, `/blog`, `/blog/:slug`, `/contacts`, `/login`, `/register`, `/account`, `/admin`.
- [ ] Обновление страницы на внутреннем адресе (например, F5 на `/services/zamena-displeynogo-modulya`) не даёт 404 — работает SPA-fallback Laravel.
- [ ] Несуществующий адрес показывает страницу 404 в стиле сайта.

## 4. Онлайн-запись (главное требование)

- [ ] На шаге 1 выбирается услуга из БД.
- [ ] На шаге 2 выбирается мастер из БД.
- [ ] На шаге 3 подгружаются **свободные даты и время именно этого мастера** — данные приходят из `schedules`.
- [ ] После записи выбранное время исчезает из свободных слотов.
- [ ] Запись появляется в `/account` у клиента и в `/admin/appointments` у администратора.
- [ ] Повторная попытка занять то же время возвращает понятную ошибку.

## 5. Админ-панель (управление контентом)

- [ ] Создание и редактирование услуги: название, категория, цены, срок, гарантия — изменения видны на сайте.
- [ ] Добавление мастера и его вывод в разделе «Мастера».
- [ ] Расписание: свободные и занятые окна по мастеру и дате, можно закрыть и освободить слот.
- [ ] Модерация отзывов: `На модерации → Опубликован` — отзыв появляется на сайте.
- [ ] Заявки на звонок: смена статуса, удаление.
- [ ] Статьи блога: создание статьи, отображение на `/blog`.
- [ ] Тексты сайта: изменение телефона или заголовка на главной сразу отражается на сайте.
- [ ] Пользователи: смена роли, блокировка, защита от удаления последнего администратора.

## 6. Модальное окно «Заказать звонок»

- [ ] Кнопка есть в шапке, подвале, на страницах «Главная», «Отзывы», «Контакты».
- [ ] Форма сохраняет лид в таблицу `leads` (проверяется в `/admin/leads`).
- [ ] Валидация: имя короче 2 символов и пустой телефон не проходят.
- [ ] После отправки появляется уведомление об успехе.

## 7. Дизайн и вёрстка

- [ ] Единая чёрно-жёлтая палитра на всех страницах, включая админку.
- [ ] Кнопки, карточки и отступы выровнены, сетки не «разъезжаются».
- [ ] Адаптив: 1440px, 1024px, 768px, 375px — меню сворачивается в «бургер», таблицы скроллятся.
- [ ] Нет горизонтальной прокрутки на мобильном.

## 8. Деплой на VPS

- [ ] Проект доступен по IP-адресу сервера, а не только локально.
- [ ] `APP_DEBUG=false`, `APP_ENV=production`.
- [ ] Выполнены `php artisan config:cache`, `route:cache`.
- [ ] Созданы отдельный пользователь MySQL и база с `utf8mb4`.
- [ ] Права `www-data` на `storage` и `bootstrap/cache`.

## 9. Полезные команды при демонстрации

```bash
# посмотреть маршруты API
php artisan route:list --path=api

# проверить подключение к БД
php artisan db:show

# пересоздать демо-данные
php artisan migrate:fresh --seed

# логи ошибок
tail -f storage/logs/laravel.log
```
