# PhoneFix — сайт сервисного центра по ремонту телефонов

Итоговый проект: **React + Laravel 11 + MySQL**.
Тематика: диагностика и ремонт телефонов, замена экранов и комплектующих, обновление ПО.
Стиль: **чёрный + жёлтый**.

## Что реализовано

| Требование из задания | Реализация |
| --- | --- |
| Стек React + Laravel + БД MySQL | `frontend/` (React 18 + Vite + Router), `backend/` (Laravel 11 API + Eloquent), MySQL |
| Минимум 2 связанные таблицы | 10 связанных таблиц: `users`, `services`, `technicians`, `schedules`, `appointments`, `reviews`, `leads`, `articles`, `settings` + служебные Laravel |
| Ролевая модель, минимум 2 роли | 3 роли: **клиент**, **мастер**, **администратор** (middleware `role:admin`) |
| Многостраничность с роутингом | 13 публичных страниц + 10 разделов админ-панели (React Router) |
| Онлайн-запись: мастер, свободная дата и время из БД | `GET /api/public/technicians/{id}/slots` + `POST /api/appointments` (транзакция, защита от двойного бронирования) |
| Личный кабинет с историей | `/account` — активные записи, история, отмена, отзыв |
| Админ-панель для управления контентом | услуги и цены, мастера, расписание, статьи, тексты сайта, отзывы, лиды, пользователи |
| Система отзывов + модерация | отзыв только по выполненной заявке, затем модерация администратором |
| Модальное окно «Заказать звонок» с сохранением лида в БД | `POST /api/public/leads` → таблица `leads` → раздел «Заявки на звонок» |
| Единый визуальный стиль, аккуратная вёрстка | дизайн-система в `frontend/src/styles/theme.css`, адаптив до 360px |
| Деплой на VPS | инструкция: [docs/DEPLOY.md](docs/DEPLOY.md) |

## Как запустить на этом компьютере

Окружение уже подготовлено, доустанавливать ничего не нужно:

| Что | Где |
| --- | --- |
| PHP 8.3.35 (portable) | `tools/php/php.exe` (+ `php.ini`, CA-сертификаты, расширения intl/pdo_mysql) |
| Composer 2 | `tools/composer.phar` |
| Зависимости Laravel | `backend/vendor` (107 пакетов) |
| База данных | **MySQL 8.0** из OSPanel — база `phonefix`, схема и демо-данные загружены |
| Настройки | `backend/.env` (создан, `APP_KEY` сгенерирован) |
| Фронтенд | собран в `backend/public/app` |

**Запуск:** двойной клик по `start-site.cmd` (или `.\start-site.ps1` из консоли).
Скрипт сам поднимет MySQL, если он не запущен, и откроет сайт на **http://127.0.0.1:4381**
(свой порт PhoneFix). Остановка — `Ctrl+C` или закрытие окна.

> **PATH настраивать не нужно.**
> `check-env.ps1` и `start-site.ps1` сначала берут PHP из `tools\php\php.exe` и Composer
> из `tools\composer.phar`, и только потом ищут системные `php`/`composer` в PATH.
> Поэтому «PHP не найден в PATH» при запуске больше не появляется.
>
> Перед стартом скрипт дополнительно проверяет сам PHP (версия, расширения
> `pdo_mysql`/`mbstring`/`openssl`/`tokenizer`/`curl`) и **реально подключается к базе
> через PHP**: если база не готова, в консоли будет причина (нет базы, неверный пароль,
> не выполнен `migrate --seed`), а не пустая страница в браузере.
>
> Если PhoneFix уже запущен на своём порту, второй сервер не поднимается — скрипт
> проверяет API и просто открывает сайт.

> **Важно: у PhoneFix свой порт — 4381.**
> На флешке три сайта: PhoneFix (`:4381`), VINPart (`E:\никита\avtozap`, `:8000`)
> и CookBook (`E:\марина\recipe-site`, `:4173`), плюс порт `4371` занят другим приложением.
> Порт PhoneFix задаётся в одном месте — `APP_URL` в `backend\.env`; `start-site.ps1`
> читает его оттуда.
> Чужие серверы скрипт **не останавливает**: если порт занят, PhoneFix сам переезжает
> на следующий свободный порт и пишет об этом в консоли. Браузер открывается только
> после того, как сервер ответил и подтвердил, что это именно PhoneFix.
>
> | Что нужно | Команда |
> | --- | --- |
> | Проверить, свободен ли порт PhoneFix | `start-site.cmd -CheckOnly` |
> | Посмотреть и остановить забытые PHP-серверы всех трёх сайтов | `stop-sites.cmd` |
> | Посмотреть, что будет остановлено, ничего не трогая | `stop-sites.cmd -WhatIfOnly` |
> | Запустить PhoneFix на другом порту | `start-site.cmd -Port 4390` |
> | Запустить строго на своём порту (без автоподбора) | `start-site.cmd -NoFallback` |

> **Если страница белая (пустой экран).**
> Сам сайт отдался, а данные не пришли — почти всегда это не запущенный MySQL.
> Теперь белого экрана нет by design:
> * `start-site.cmd` не открывает браузер, пока API не ответит, и пишет причину в консоль
>   (включая хвост лога `runtime\mysql.log`, если MySQL не смог стартовать);
> * в самой странице есть аварийный экран загрузки и ErrorBoundary — вместо пустоты
>   появляется сообщение с кнопкой «Проверить снова»;
> * если API недоступен, поверх сайта показывается жёлтая плашка «Нет связи с базой данных».
>
> Проверить окружение: `check-env.cmd`, раздел «Соединение с базой данных».
> MySQL из OSPanel (модуль **MySQL-8.0**) слушает `127.0.1.30:3306` — именно этот адрес
> указан в `backend\.env` (`DB_HOST`).

**Запуск через OSPanel:** проект уже подключён к вашей OSPanel (`D:\OSPanel`) —
привязка `D:\OSPanel\home\phonefix.local` → `backend`, настройки в `backend\.osp\project.ini`,
домен `phonefix.local` прописан в `hosts`. Достаточно запустить OSPanel от имени администратора,
включить модули **Apache, PHP 8.3 и MySQL-8.0** и открыть http://phonefix.local

```powershell
.\start-site.cmd          # запуск сайта (поднимает MySQL при необходимости)
.\check-env.cmd           # проверка окружения
.\run-tests.cmd           # автотесты (61 тест, SQLite в памяти — рабочая база не затрагивается)
```

> В OSPanel у каждого модуля свой IP: MySQL слушает `127.0.1.30:3306` — именно это указано
> в `backend/.env` (`DB_HOST`). Если поднимаете MySQL иначе (например, на `127.0.0.1`),
> поправьте `DB_HOST` в `.env`.

Если нужно доустановить PHP-пакет:

```powershell
cd backend
..\tools\php\php.exe ..\tools\composer.phar require <пакет>
```

> В `backend/composer.json` закреплено `symfony/console: ~7.3.0`: в ветке 7.4 команды
> `php artisan` ломаются (Symfony обходит переопределённый метод Laravel), поэтому
> при обновлении зависимостей это ограничение снимать не стоит.
>
> Composer настроен на зеркало `mirrors.aliyun.com/composer` (`tools/composer-home/config.json`),
> потому что репозиторий packagist.org с этой машины недоступен.

## Предпросмотр дизайна без установки

Если PHP и MySQL ещё не подняты, а посмотреть на сайт хочется прямо сейчас — откройте
[`preview/index.html`](preview/index.html) двойным кликом. Это автономная демонстрация дизайна
(чёрно-жёлтая тема, те же тексты, цены, услуги и мастера, что и в сидерах): главная, услуги с фильтром
по категориям, прайс, мастера, форма записи, отзывы, контакты и модальное окно «Заказать звонок».
Никаких зависимостей и сервера не требуется — это витрина вёрстки, а не рабочая версия.
Рабочая версия с базой данных — `frontend/` + `backend/`.

## Быстрый старт (локально, OSPanel)

Подробно — в [docs/DEPLOY.md](docs/DEPLOY.md). Коротко:

```bash
# 1. База данных
mysql -u root -e "CREATE DATABASE phonefix CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2. Бэкенд
cd backend
composer install
copy .env.example .env      # Windows; в Linux: cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan storage:link

# 3. Фронтенд
cd ../frontend
npm install
npm run dev                 # http://127.0.0.1:5273 (API проксируется на :4381)

# сборка в Laravel: файлы попадут в backend/public/app
npm run build
```

## Проверка перед запуском и автотесты

Перед первым запуском удобно прогнать две проверки — они подскажут, чего не хватает:

```powershell
# из корня проекта: версии PHP/Node, расширения PHP, соединение с MySQL, наличие файлов
.\check-env.ps1

# 61 автотест на SQLite в памяти (рабочая база MySQL не затрагивается)
.\run-tests.ps1
```

Если PowerShell отказывается запускать скрипты («running scripts is disabled»), используйте
`.cmd`-обёртки — они обходят политику запуска автоматически:

```
check-env.cmd      # двойной клик или запуск из консоли
run-tests.cmd
```

Тесты покрывают ключевые сценарии: регистрацию и вход, роли и доступ к админке,
онлайн-запись, невозможность занять одно время дважды, отмену заявки с освобождением слота,
отзывы с модерацией, лиды из модального окна и управление контентом из админки.
